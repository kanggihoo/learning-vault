Kafka Producer 설정 치트시트

실제 설정 시 참고용 — 전체 목록(보안/SASL/SSL 포함 수백 개)은 공식 문서 Producer Configs 참고. 사고 방식은 0028 레슨, 개념적 배경은 0019 레슨 참고.

1. 안전성 (Durability)

Config기본값의미
acksall0=응답 안 기다림, 1=leader만, all=ISR 전체가 받아야 성공
enable.idempotencetrue재전송돼도 중복 없이 정확히 한 번 기록
transactional.idnull설정하면 트랜잭션 프로듀서로 동작(exactly-once)

2. 처리량 (Throughput)

Config기본값의미
batch.size16384 bytespartition별 batch 상한. 작으면 batching 감소, 크면 메모리 다소 낭비
linger.ms5batch가 안 차도 이 시간 지나면 전송(Kafka 4.0부터 기본 0→5로 변경)
compression.typenonenone/gzip/snappy/lz4/zstd — batch 전체를 묶어서 압축
buffer.memory33554432 (32MB)전송 대기 record용 총 buffer. 가득 차면 max.block.ms 동안 block
max.request.size1048576 (1MB)요청 하나의 최대 크기 상한

3. 재시도 / Timeout

Config기본값의미
delivery.timeout.ms120000 (2분)send() 이후 최종 성공/실패 확정까지의 전체 상한. ≥ request.timeout.ms + linger.ms 필요
request.timeout.ms30000 (30초)요청 한 번의 응답 대기 시간
retries사실상 무한보통 직접 안 만지고 delivery.timeout.ms로 제어 권장
retry.backoff.ms100재시도 전 대기 시간(지수 증가)
max.block.ms60000 (1분)send()/partitionsFor() 등이 최대 block하는 시간

4. 순서 / Partitioning

Config기본값의미
max.in.flight.requests.per.connection5idempotence=false면 >1일 때 순서 뒤바뀜 위험. idempotence=true면 5까지 안전
partitioner.classnull(기본 전략)key 있으면 hash, 없으면 sticky partitioning
partitioner.ignore.keysfalsetrue면 key 있어도 sticky partitioning 사용
partitioner.adaptive.partitioning.enabletrue느린 broker로는 덜 보내도록 적응

5. 연결 / 식별

Config기본값의미
bootstrap.servers없음(필수)클러스터 초기 접속용 host:port 목록. 전체 브로커 아니어도 됨(2개 이상 권장)
client.id""Quota·모니터링에서 이 클라이언트를 식별하는 이름표
key.serializer / value.serializer없음(필수)key/value를 byte로 변환하는 클래스
metadata.max.age.ms300000 (5분)변화가 없어도 이 주기로 메타데이터 강제 새로고침
