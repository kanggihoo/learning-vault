§1 · 용어집 — 층별로

와이어 프로토콜 메시지 층 · 호스트 AI 앱 구현 층 · 컨텍스트 LLM 토큰 창 층

기본 골격

Host (호스트)
AI 애플리케이션 자체. Claude Code, Claude Desktop, VS Code. 여러 클라이언트를 만들어 관리하고, 모델에 무엇을 보여줄지 결정한다. 피할 말: "MCP 앱", "에이전트"(에이전트는 호스트 안에서 도는 것)
Client (클라이언트)
호스트가 서버 하나당 하나 만드는 연결 담당자. 1:1 관계. 호스트가 서버 3개를 쓰면 클라이언트도 3개.
Server (서버)
도구·리소스·프롬프트를 제공하는 프로그램. 로컬 프로세스(stdio)일 수도, 원격 HTTP 서비스일 수도 있다. "서버"는 위치가 아니라 역할이다 — 내 노트북에서 돌아도 서버.
Primitive (프리미티브)
서버가 내놓는 세 가지 기본 단위 — Tools(모델이 호출하는 함수), Resources(읽을 데이터), Prompts(템플릿). 각각 */list로 목록, tools/call·resources/read·prompts/get로 사용.
JSON-RPC 2.0
MCP 메시지의 봉투 형식. { jsonrpc, id, method, params }가 요청, { id, result }가 응답, id 없는 { method }가 알림(notification, 답 없음).
Transport (전송)
JSON-RPC를 실어 나르는 통로. stdio(자식 프로세스의 표준 입출력, 한 줄에 한 메시지) · Streamable HTTP(POST 한 번에 요청 하나, 응답은 JSON 한 덩이 또는 SSE 스트림).
SSE (Server-Sent Events)
HTTP 응답을 끊지 않고 이벤트를 계속 흘려보내는 표준. 진행률 알림처럼 "답이 여러 조각"일 때 서버가 이걸 고른다.
Capability (기능 선언)
"나는 tools를 지원한다", "나는 elicitation을 받을 수 있다" 같은 지원 기능 목록. 상대가 선언하지 않은 기능은 쓰면 안 된다.

이번 판에서 새로 나온 말

Stateless (무상태)
"요청을 처리하는 데 필요한 정보가 전부 그 요청 안에 있다." 서버는 이전 요청을 기억하지 않는다. 같은 연결 위의 앞선 메시지도 문맥으로 쓰면 안 된다. HTTP가 원래 무상태인 것과 같은 뜻. 쿠키·세션은 그 위에 덧댄 것이었다.
Session (세션) ①
이전 판의 프로토콜 세션. initialize로 열고 Mcp-Session-Id 헤더로 이어 가던 "연결의 기억". 2026-07-28에서 제거됨. §3 — LLM 대화 컨텍스트(세션 ②)와 헷갈리기 쉽다.
_meta
모든 요청·응답에 붙는 메타데이터 가방. 이번 판에서 매 요청 필수인 두 키 — io.modelcontextprotocol/protocolVersion(내가 말하는 판), io.modelcontextprotocol/clientCapabilities(내가 받을 수 있는 기능). 권장 키 clientInfo. 세션이 하던 일을 이 가방이 대신한다.
server/discover
"당신은 어떤 판을 지원하고 무슨 기능이 있나요?"를 한 번에 묻는 새 RPC. 서버는 반드시 구현, 클라이언트는 불러도 안 불러도 됨(바로 다른 요청을 보내고 버전 에러가 오면 맞추면 된다). stdio에서는 "이 서버가 옛 판인지 새 판인지" 알아보는 탐침으로 쓴다.
resultType
모든 응답에 붙는 필드. "complete"(끝났다) 또는 "input_required"(더 필요한 게 있다 — 아래 MRTR). 옛 서버가 안 보내면 "complete"로 간주.
MRTR (Multi Round-Trip Requests)
서버가 사용자에게 뭔가 물어야 할 때(확인, 빠진 값) 서버가 요청을 보내는 대신, 원래 요청의 답으로 input_required와 "필요한 것 목록"(inputRequests)을 돌려주는 패턴. 클라이언트가 답(inputResponses)을 채워 같은 요청을 다시 보낸다. 비유: 서류 미비 → 보완 후 재접수. 창구 직원(서버 인스턴스)이 바뀌어도 된다.
requestState
MRTR에서 서버가 "재접수할 때 이걸 그대로 들고 오세요"라고 주는 불투명한 문자열. 서버가 자기 상태를 여기에 봉인해 두므로 서버는 아무것도 기억하지 않아도 된다. 클라이언트는 열어 보거나 고치면 안 된다. 서버는 공격자 입력으로 취급해 HMAC/AEAD로 무결성을 지킨다. 백엔드 비유: 서명된 쿠키 / JWT.
Elicitation (사용자에게 묻기)
서버가 사용자에게 폼이나 확인을 요청하는 클라이언트 기능. 이번 판에서 유일하게 살아남은 클라이언트 프리미티브(Sampling·Roots는 폐기). MRTR 안에 실려 간다.
subscriptions/listen
"도구 목록이 바뀌면 알려 줘" 같은 변경 알림을 받으려고 여는 긴 요청. 응답이 닫히지 않는 SSE 스트림이고, 원하는 알림 종류를 필터로 고른다. 옛 판의 HTTP GET 스트림과 resources/subscribe를 대체.
ttlMs / cacheScope
tools/list 등 목록 응답에 붙는 캐시 힌트. ttlMs는 "이만큼 ms 동안은 다시 안 물어도 됨"(HTTP max-age 유사), cacheScope는 public(누구와 공유돼도 됨) / private(같은 인증 문맥에서만). 알림이 오면 TTL이 남아도 즉시 무효.
Mcp-Method / Mcp-Name
HTTP 요청 헤더에 메서드명과 도구명을 복사해 두는 규칙. 게이트웨이·WAF·레이트리미터가 JSON 본문을 열지 않고 라우팅·계량할 수 있게. 본문과 다르면 서버가 -32020 HeaderMismatch로 거절.
SEP
Specification Enhancement Proposal. 스펙 변경 제안 문서. 번호가 GitHub PR 번호다. "왜 이렇게 바뀌었나"는 SEP PR 스레드에 있다.
Deprecated / Removed
폐기 예정 / 삭제. 이번 판부터 공식 정책 — 최소 12개월 Deprecated 상태를 거친 뒤에만 Removed. 보안 사고 시 예외적으로 90일까지 단축.

"점진적 도구 로딩"의 말들

Context window (컨텍스트 창)
모델이 한 번의 호출에서 읽을 수 있는 토큰의 총량. 시스템 프롬프트 + 도구 정의 + 대화 + 도구 결과가 전부 여기서 경쟁한다.
Tool definition (도구 정의)
이름 + 설명 + 입력 JSON Schema(+ 출력 스키마). 도구 하나가 수백 토큰. 서버 5개면 수만 토큰이 사용자가 한 글자 치기 전에 소비된다.
Progressive (tool) discovery
MCP 공식 docs의 용어. "호스트가 tools/list로 정의를 가져오되, 모델 컨텍스트에 넣는 것은 미룬다." 모델에는 가벼운 search_tools 메타툴만 주고, 필요할 때 해당 도구 정의만 넣는다. 스펙(와이어) 변경이 아니다 — 호스트 구현 패턴이다.
Meta-tool (메타툴)
도구를 찾거나 부르기 위한 도구. search_tools, get_tool_details, call_tool. Claude Code에서는 ToolSearch.
defer_loading
Anthropic API의 도구 정의 옵션. true면 정의를 요청에는 보내지만 모델 컨텍스트에는 넣지 않는다. 모델이 tool search로 찾을 때만 들어간다.
tool_reference
검색 결과로 돌아오는 "이 도구를 가리키는 손가락". API가 이걸 대화 중간에 전체 정의로 펼쳐 모델에 보여 준다. 프롬프트 앞부분(프리픽스)은 건드리지 않는다.
Prompt cache (프롬프트 캐시)
같은 프롬프트 앞부분을 재사용해 비용·지연을 줄이는 제공자 기능. 도구 배열이 바뀌면 캐시가 깨진다. 그래서 스펙이 "tools/list는 결정적 순서로" 라고 권고하고, docs가 "새 정의는 캐시 경계 뒤에 덧붙이라"고 한다.
Threshold (임계값)
"도구 정의가 컨텍스트의 몇 %를 넘으면 점진 로딩으로 전환하나." MCP docs 권고 1~5%. Claude Code ENABLE_TOOL_SEARCH=auto 기본 10%.
