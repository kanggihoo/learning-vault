Git rebase 협업 치트시트

판단 기준: 내가 바꾸려는 커밋을 다른 사람이 이미 pull 해서 그 위에 작업했을 가능성이 있나? 가능성이 있으면 rebase로 공개 이력을 다시 쓰지 않는다.

써도 되는 rebase

아직 push 안 한 개인 커밋 정리

git rebase -i HEAD~3

메시지 수정, squash, commit 순서 정리에 적합하다.

내 PR 브랜치를 최신 main 위로 재배치

git fetch origin
git switch feature/login
git rebase origin/main
git push --force-with-lease

이 브랜치를 나 혼자 쓰거나, 팀 규칙상 PR 브랜치 rebase가 허용될 때 사용한다.

pull 시 로컬 커밋을 위로 올리기

git pull --rebase origin main

공유 브랜치에 직접 커밋하지 않는다는 전제가 있을 때 로컬 merge commit을 줄인다.

피해야 하는 rebase

공유 브랜치 이력 재작성

git switch main
git rebase ...
git push --force

다른 사람이 이미 기반으로 삼은 커밋 해시를 사라지게 만든다.

여러 명이 같이 작업 중인 feature 브랜치

git rebase origin/main
git push --force

팀원이 같은 브랜치 위에 작업 중이면 그 사람의 기준점이 바뀐다.

무조건 force push

git push --force

원격에 새 커밋이 추가됐는지 확인하지 않고 덮어쓸 수 있다. 필요하면 --force-with-lease를 쓴다.

자주 쓰는 협업 명령어

# 상태와 이력 확인
git status
git log --oneline --graph --decorate --all
git diff
git diff --staged

# 원격 최신 정보만 가져오기
git fetch origin
git fetch --prune

# 브랜치 이동과 생성
git switch main
git switch -c feature/login
git branch -vv

# 통합
git merge origin/main
git merge --no-ff feature/login
git rebase origin/main
git rebase -i HEAD~3

# 충돌 처리 중
git status
git add <file>
git rebase --continue
git rebase --abort
git merge --abort

# push
git push -u origin feature/login
git push --force-with-lease

# 임시 보관
git stash push -m "wip login"
git stash list
git stash pop
