Kafka Connect 설정 치트시트

실제 설정 시 참고용 — 전체 목록은 공식 문서 Kafka Connect Configs 참고. 개념 설명은 0029 레슨 참고.

1. Worker 설정 (필수)

설정기본값메모
bootstrap.servers-Kafka 클러스터 접속 주소 목록
group.id-Distributed mode에서 이 워커가 속한 Connect 클러스터 식별자
key.converter / value.converter-메시지 key/value 직렬화 포맷 (JSON, Avro 등)
header.converterSimpleHeaderConverter메시지 header 직렬화 포맷
exactly.once.source.supportdisabled클러스터 전체 exactly-once 지원 여부 — preparing → enabled 순으로 롤링 적용

2. Connect의 내부 상태 토픽 (Worker 설정)

설정기본값메모
offset.storage.topic-source connector offset 저장
config.storage.topic-connector 설정 저장
status.storage.topic-connector/task 상태 저장
offset.storage.partitions25offset topic partition 수
status.storage.partitions5status topic partition 수
{offset|config|status}.storage.replication.factor3낮추지 말 것 — 이 토픽 유실 = Connect 상태 유실
offset.flush.interval.ms60000offset commit 주기

3. Worker 운영/디버깅

설정기본값메모
plugin.pathnull커넥터 plugin jar 디렉터리 목록
listenershttp://:8083REST API 주소
rest.advertised.host.name / .portnull다른 워커에게 알려줄 자기 주소 (멀티 워커 환경에서 필요할 수 있음)
scheduled.rebalance.max.delay.ms300000워커가 잠깐 사라졌을 때 재배정을 늦춰 기다려주는 최대 시간
task.shutdown.graceful.timeout.ms5000task 정상 종료 대기 시간(전체 합)
connector.client.config.override.policyAll커넥터가 client 설정(producer/consumer)을 얼마나 덮어쓸 수 있는지

4. Connector 설정 — Source/Sink 공통

설정기본값메모
name-커넥터 고유 이름
connector.class-커넥터 구현체 클래스/alias
tasks.max1병렬 task 수 — 처리량 부족 시 증가
transforms / predicates""SMT(Single Message Transform) alias 목록
config.action.reloadrestart외부 config provider 값 변경 시 재시작 여부

5. Connector 설정 — Source 전용

설정기본값메모
exactly.once.supportrequestedrequired이면 exactly-once 미지원 시 생성 자체가 실패
transaction.boundarypollpoll/interval/connector 중 언제 transaction을 commit할지
offsets.storage.topicnull커넥터별 별도 offset 토픽 (미지정 시 worker 공용 토픽 사용)
topic.creation.groups""source connector가 만드는 토픽의 설정 그룹

6. Connector 설정 — Sink 전용

설정기본값메모
topics / topics.regex""읽어올 토픽 목록 또는 정규식 — 둘 중 하나만
errors.tolerancenoneall로 바꾸면 문제 레코드를 건너뛰고 계속 진행
errors.log.enable / errors.log.include.messagesfalse실패 상세를 로그에 남길지 (메시지 내용까지 남길지는 별도 설정)
errors.deadletterqueue.topic.name""실패 레코드를 보관할 DLQ 토픽 — 비어있으면 DLQ 안 씀
errors.deadletterqueue.topic.replication.factor3DLQ 토픽 생성 시 replication factor
errors.retry.timeout / errors.retry.delay.max.ms0 / 60000재시도 총 허용 시간(0=재시도 안 함, -1=무한) / 재시도 간 최대 지연
