규칙 — 외울 것은 이 한 줄

게임 1개월 = 실제 720초 (12분). 고정.
틱 간격은 규칙이 아니라 파생값이다 — 720 ÷ N, 31~36초 유동.

틱 시각 계산

✓ tickAt(k) = 월시작실제시각 + round(720 × k ÷ N)      k = 1..N
      N = 그 달의 거래일 수 = 한국 · 미국 거래일의 합집합   (기획서 4.1.4)

✗ tickAt(k) = tickAt(k-1) + 간격      // 지연 누적 (fixedDelay)
✗ tickAt(k) = 월시작 + 35초 × k       // 간격이 상수가 아님 (fixedRate)

왜 안 밀리나: k = N이면 값이 정확히 720. 반올림 오차가 월 경계를 넘지 못한다.

운영 — 틱 지연이 지표가 되는 이유

tickAt(k)가 절대 시각이므로 예정 − 실제 발행이 그대로 지연 지표가 된다 (adm.md F-ADM-05). 간격 기반이었다면 밀린 것이 새 기준이 되어 지연이 안 잡힌다.

스케줄러 기본 스레드는 1개. scheduleAtFixedRate는 겹쳐 실행하지 않으므로 ("may start late, but will not concurrently execute") 틱 처리가 31초를 넘기면 다음 틱이 늦게 나간다. 한 틱에서 하는 일: 28종 가격·환율 → 예약 전건 판정 → 전 계좌 순회(순위 + 히트맵 + 평가액을 같은 순회에서) → 개인 메시지 발행.
