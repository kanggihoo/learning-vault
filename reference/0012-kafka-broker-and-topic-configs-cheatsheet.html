Kafka Broker & Topic 설정 치트시트

실제 설정 시 참고용 — 전체 목록(수백 개)은 공식 문서 Broker Configs / Topic Configs 참고. 사고 방식은 0026 레슨 참고. "Topic 레벨" 표시가 있는 설정은 Broker 기본값을 토픽별로 override할 수 있다.

1. 저장·보관(Retention)

설정레벨기본값의미
log.retention.ms / retention.msBroker / Topic7일이 시간 지나면 segment 삭제(-1=무제한)
log.retention.bytes / retention.bytesBroker / Topic무제한(-1)partition 크기 상한
log.segment.bytes / segment.bytesBroker / Topic1GiB단일 로그 파일 최대 크기
log.roll.ms / segment.msBroker / Topic7일segment가 안 찼어도 이 시간 지나면 강제 롤링
cleanup.policyBroker(log.cleanup.policy) / Topicdeletecompact=key별 최신값만 유지(Log Compaction)
min.cleanable.dirty.ratioBroker / Topic0.5compaction 실행 빈도 — 낮을수록 자주 compact, 디스크 덜 낭비
delete.retention.msBroker(log.cleaner.delete.retention.ms) / Topic1일compact topic의 tombstone(삭제 표시) 보존 시간
message.max.bytes / max.message.bytesBroker / Topic~1MB허용되는 최대 메시지(배치) 크기

2. 복제·안전성

설정레벨기본값의미
default.replication.factorBroker1운영에서는 3으로 반드시 상향
min.insync.replicasBroker / Topic1acks=all과 함께 2 이상 권장
unclean.leader.election.enableBroker / Topicfalsetrue=가용성 우선(데이터 손실 가능), false=일관성 우선
replica.lag.time.max.msBroker30초이 시간 이상 못 따라오면 ISR에서 제외
auto.leader.rebalance.enableBrokertrueLeader가 불균형해지면 주기적으로 preferred leader로 재조정
num.replica.fetchersBroker1Follower가 Leader로부터 복제해오는 스레드 수 — 늘리면 복제 처리량↑, CPU/메모리 비용↑

3. 네트워크·스레드

설정기본값의미
listenersPLAINTEXT://:9092어디서 접속을 받을지
advertised.listenerslisteners 값과 동일클라이언트에게 광고할 접속 주소 — 클라우드/컨테이너에서 반드시 별도 설정 확인
num.network.threads3네트워크 요청 송수신 스레드 — 리스너별 별도 풀
num.io.threads8디스크 I/O 포함 요청 처리 스레드
socket.receive/send.buffer.bytes100KiB소켓 버퍼 크기(-1=OS 기본값)
connections.max.idle.ms10분이 시간 유휴 상태인 연결을 닫음
auto.create.topics.enabletrue운영에서는 오타로 인한 topic 난립 방지 위해 false 고려
delete.topic.enabletruefalse면 admin의 topic 삭제 요청을 브로커가 거부

4. KRaft 전용 (자세한 개념은 0022 레슨)

설정의미
process.rolesbroker / controller / 둘 다
node.idKRaft 모드 필수 고유 노드 번호
controller.quorum.bootstrap.serversDynamic Quorum 진입점 목록
controller.quorum.votersStatic Quorum 방식(구식) — Dynamic 사용 시 설정하지 않음
controller.listener.namesController 쿼럼 통신용 리스너 이름
metadata.log.dirmetadata log 저장 위치(미지정 시 log.dirs 첫 번째 사용)

5. 내부 토픽 (offsets / transaction / share-group)

설정기본값의미
offsets.topic.replication.factor3__consumer_offsets 내부 topic 복제본 수
offsets.topic.num.partitions50배포 후 변경 비권장
offsets.retention.minutes10080(7일)그룹이 비거나 오래 커밋 안 하면 이 시간 후 offset 만료
transaction.state.log.replication.factor3트랜잭션 상태 내부 topic 복제본 수
transaction.max.timeout.ms15분트랜잭션이 허용하는 최대 timeout
transactional.id.expiration.ms7일이 시간 동안 활동 없으면 transactional.id 만료

6. Quota (자세한 개념은 0019 §10 레슨)

설정의미
quota.producer.default / quota.consumer.defaultclient 전체에 적용되는 기본 byte/sec 제한
(user, client-id) 단위 동적 quotakafka-configs.sh --entity-type clients로 개별 설정 — 코드 재배포 없이 적용

전체 목록은 원문(Broker/Topic Configs) 참고 — 여기는 실무 도입 판단에 자주 걸리는 항목만 추렸다.
