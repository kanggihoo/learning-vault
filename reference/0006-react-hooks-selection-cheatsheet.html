React Hooks 선택 치트시트

핵심: Hook은 이름으로 외우지 말고 문제로 고른다. 외부 동기화는 useEffect, 렌더링과 무관한 보관은 useRef, 값 캐시는 useMemo, 함수 캐시는 useCallback, 복잡한 상태 규칙은 useReducer.

선택 알고리즘

화면에 보여야 하는 값인가?
  yes -> useState / useReducer
  no  -> useRef 후보

React 밖과 연결하는가?
  yes -> useEffect
  no  -> useEffect 제거 후보

성능 때문에 재사용하려는가?
  계산 결과 -> useMemo
  함수 참조 -> useCallback

상태 변경 규칙이 복잡한가?
  yes -> useReducer

빠른 표

Hook 한 줄 정의 대표 상황 주의
useEffect 렌더링 후 외부 시스템과 동기화. fetch, 구독, timer, DOM 이벤트, 외부 widget. 외부 시스템이 없으면 대개 필요 없다.
useRef 렌더링과 무관한 값을 보관. DOM node, interval id, 이전 값, ignore flag. current 변경은 re-render를 만들지 않는다.
useMemo 계산 결과를 의존성 기준으로 재사용. 큰 배열 filter/sort, 비싼 계산, stable object prop. 정확성 수단이 아니라 성능 최적화다.
useCallback 함수 참조를 의존성 기준으로 재사용. memo 자식의 함수 prop, custom Hook 반환 함수. 모든 함수에 붙이는 습관은 불필요하다.
useReducer state + action -> next state 규칙 관리. form, wizard, editor, 비동기 상태 전이. reducer는 순수 함수여야 한다.

암기 문장

useEffect   = 밖이랑 연결
useRef      = 기억만 하고 조용히 보관
useMemo     = 계산한 값 캐시
useCallback = 함수 자체 캐시
useReducer  = 상태 변경 규칙표

짧은 예시

// 외부 연결
useEffect(() => {
  window.addEventListener("resize", onResize);
  return () => window.removeEventListener("resize", onResize);
}, [onResize]);

// 렌더링 없는 보관
const timerIdRef = useRef(null);

// 값 캐시
const filtered = useMemo(() => filter(items, query), [items, query]);

// 함수 캐시
const onSelect = useCallback((id) => setSelectedId(id), []);

// 상태 규칙
const [state, dispatch] = useReducer(reducer, initialState);
