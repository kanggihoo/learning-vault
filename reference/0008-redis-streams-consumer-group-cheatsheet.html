Redis Streams Consumer Group 치트시트

핵심: Consumer Group은 Stream을 여러 Worker에게 "나눠" 소비하게 만든다. 한 메시지는 한 Worker에게만 배달되고, XACK 전까지는 PEL에 남아 회수 가능하다.

한 줄 모델

XREAD만       = 모든 Worker가 모든 메시지 수신 (브로드캐스트)
Consumer Group = 한 메시지 = 한 Worker (분배)
PEL            = "배달됐지만 아직 XACK 안 됨" 목록
XACK           = "처리 완료 확정" → PEL에서 제거
XAUTOCLAIM     = idle 한 죽은 Worker의 pending 회수 (delivery count 증가)

핵심 명령어

최초 1회     XGROUP CREATE jobs:ai ai-workers $ MKSTREAM
             ($ = 생성 시점 이후의 새 메시지만)

Worker 루프 XREADGROUP GROUP ai-workers worker-1 BLOCK 0 COUNT 10 STREAMS jobs:ai >
             (> = "아무에게도 배달 안 된 새 메시지")

처리 완료    XACK jobs:ai ai-workers <message-id>
             (PEL에서 제거 = "확실히 끝냄")

죽은 W 회수  XAUTOCLAIM jobs:ai ai-workers worker-2 60000 0
             (idle ≥ 60초 pending 회수, delivery count 증가)

PEL 점검     XPENDING jobs:ai ai-workers            (요약: 총 수·consumer별)
             XPENDING jobs:ai ai-workers - + 10      (상세: ID·소유자·idle·delivery)

XREADGROUP의 두 모드 (자주 헷갈림)

>   새 메시지만. "아직 아무에게도 배달 안 된 것". 정상 작업 루프.
0   내 pending만. "이전에 내게 왔는데 아직 XACK 안 한 것". 재시작 복구용.

Worker 재시작 표준 패턴:
  1. 먼저 STREAMS key 0 으로 자기 pending 처리 + XACK
  2. pending이 비면 그제야 STREAMS key > 로 새 메시지

핵심 용어

Consumer Group   Stream을 분배 단위로 소비하는 Worker 그룹. 한 메시지=한 Worker.
consumer         그룹 내 개별 Worker 이름. XREADGROUP 호출 시 자동 등록.
PEL              Pending Entries List. 배달됐지만 XACK 안 된 메시지 목록.
XACK             "처리 완료" 통보. PEL에서 메시지 제거의 유일한 방법.
XAUTOCLAIM       idle time 경과한 다른 consumer의 pending을 회수. delivery count 증가.
min-idle-time    회수 임계값(ms). "이 시간 지나면 정상 처리가 아니라 죽었거나 멈춘 것".
delivery count   재전달/회수된 횟수. 한계 도달 시 DLQ로 에스컬레이션.
> (special ID)   "새 메시지만" 표시.
0 (ID)           "내 pending만" 표시.

Worker 사망 시 회수 흐름

worker-1 이 XACK 전 사망
  → 메시지 M 은 PEL에 남음 (소유자=worker-1, idle 증가)
  → 회수 루프: XPENDING 점검 → idle ≥ min-idle-time 인 M 발견
  → XAUTOCLAIM 이 M 소유권을 worker-2 로 이전
  → worker-2 재처리 → 성공 시 XACK
  → 반복 실패 시 delivery count 한계 → DLQ + FAILED

왜 Consumer Group인가 (vs XREAD만)

              XREAD만          Consumer Group
분배          중복 수신(전부)   한 메시지=한 Worker
추적(PEL)     불가              가능 (누가 뭘 들고 있나)
회수          불가 (죽으면 유실) 가능 (XAUTOCLAIM)
확정(XACK)    개념 없음          "확실히 끝냄" 명시

→ Worker 분산 + 장애 복구가 필요하면 Consumer Group은 전제.

다음 개념으로 연결

한 메시지=한 Worker 이지만, XAUTOCLAIM 회수로 중복 전달 가능(at-least-once)
→ Consumer 멱등성(idempotency) 필수 (다음 레슨)
→ delivery count 한계 → DLQ + FAILED (Outbox 레슨과 합류)
→ lease 만료(DB) = min-idle-time(Redis) = 같은 임계값
