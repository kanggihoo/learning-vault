GoF 23패턴 목차

GoF = 책 Design Patterns(1994)의 네 저자. 이 책이 소개한 패턴이 23개다. 목적에 따라 생성 5 · 구조 7 · 행위 11로 나눈다.

분류질문한 줄 비유개수
생성 Creational객체를 어떻게 만들까공장5
구조 Structural클래스·객체를 어떻게 조합할까레고 조립7
행위 Behavioral객체들이 어떻게 협력하고 책임을 나눌까팀 업무 분담11

범위(Scope): 주황색 = 클래스 패턴(상속, 컴파일 시점 고정). 나머지는 객체 패턴(합성·위임, 실행 중 변경 가능). 클래스 패턴은 Factory Method · Adapter · Interpreter · Template Method 4개 — 외우기 "팩어인템". Adapter는 클래스 어댑터(상속)와 객체 어댑터(합성) 두 형태가 있다.

생성 패턴 5개 — "객체를 어떻게 만들까"

패턴한 줄 설명비유묶음
Abstract Factory
추상 팩토리 · Kit		서로 어울리는 객체 묶음(제품군)을 구체 클래스 지정 없이 만든다가구 브랜드 "모던 세트"6
Builder
빌더		복잡한 객체를 단계별로 조립한다. 같은 절차로 다른 결과를 만든다햄버거 주문6
Factory Method
팩토리 메서드 · Virtual Constructor		생성 메서드는 부모가 선언하고 무엇을 만들지는 서브클래스가 정한다프랜차이즈 지점이 빵 종류를 결정6
Prototype
프로토타입		기존 객체를 복제(clone)해서 새 객체를 만든다"다른 이름으로 저장"6
Singleton
싱글톤		인스턴스를 하나만 만들고 전역 접근점을 준다나라의 대통령6

구조 패턴 7개 — "어떻게 조합할까"

패턴한 줄 설명비유묶음
Adapter
어댑터 · Wrapper		맞지 않는 인터페이스를 기대하는 모양으로 변환해 같이 쓰게 한다돼지코 변환 플러그2
Bridge
브리지		기능 계층과 구현 계층을 분리해 각각 독립 확장한다리모컨 종류 × TV 제조사4
Composite
컴포지트		부분-전체를 트리로 만들고 개별/복합 객체를 똑같이 다룬다폴더 안의 파일과 폴더4
Decorator
데코레이터 · Wrapper		객체를 감싸서 기능을 동적으로 추가한다 (상속 대신)커피에 샷·시럽 추가2
Facade
퍼사드		복잡한 서브시스템 앞에 단순한 창구 하나를 둔다호텔 컨시어지4
Flyweight
플라이웨이트		같은 데이터를 공유해 대량 객체의 메모리를 줄인다숲의 나무 1만 그루가 모델 공유4
Proxy
프록시 · Surrogate		대리자를 세워 접근을 제어한다 (지연 생성·권한·원격)연예인 매니저2

행위 패턴 11개 — "어떻게 협력하고 책임을 나눌까"

패턴한 줄 설명비유묶음
Chain of Responsibility
책임 연쇄		처리할 수 있는 객체가 나올 때까지 요청을 사슬로 넘긴다대리 → 과장 → 부장 결재3
Command
커맨드 · Action		요청 자체를 객체로 만들어 저장·큐잉·취소(undo)한다식당 주문서3
Interpreter
인터프리터		언어의 문법을 클래스로 표현하고 문장을 해석한다수식 계산기, 정규식5
Iterator
반복자 · Cursor		내부 구조를 숨기고 요소를 순서대로 꺼낸다TV 채널 다음/이전5
Mediator
중재자		객체끼리 직접 말하지 않고 중재자를 거친다 (N:N → 1:N)공항 관제탑3
Memento
메멘토 · Token		캡슐화를 깨지 않고 상태를 저장했다가 복원한다게임 세이브5
Observer
옵서버 · Publish-Subscribe		상태가 바뀌면 의존하는 객체들에게 자동 통지한다 (1:N)유튜브 구독 알림3
State
상태		내부 상태가 바뀌면 행동이 바뀐다. 상태를 객체로 분리한다자판기1
Strategy
전략 · Policy		알고리즘을 캡슐화해 서로 교체할 수 있게 한다내비 경로 선택1
Template Method
템플릿 메서드		부모가 알고리즘 골격을 정하고 일부 단계를 자식이 채운다라면 끓이기 순서1
Visitor
방문자		요소 클래스를 수정하지 않고 새 연산을 별도 클래스로 추가한다검침원·배달원이 각자 방문5

학습 순서 (한 묶음 = 한 분류, 6묶음)

묶음분류패턴구분의 핵심
1행위Strategy / State / Template Method상속인가 합성인가, 누가 바꾸나
2구조Decorator / Proxy / Adapter인터페이스를 같게 두는가, 바꾸는가
3행위Observer / Mediator / Chain of Responsibility / Command요청이 어디로 가는가
4구조Composite / Facade / Bridge / Flyweight트리·창구·분리·공유
5행위Iterator / Visitor / Memento / Interpreter순회·연산 분리·상태 저장·문법
6생성Factory Method / Abstract Factory / Builder / Prototype / Singleton무엇을 어떻게 만드는가 (복습 중심)

생성 패턴은 이미 본 적이 있다고 해서 뒤로 보냈고, 구조·행위를 앞에 둔다. 퀴즈에서 실제로 틀린 쌍을 보고 계속 조정한다. 출처 주의: 위 한 줄 설명은 시험 대비 정리본과 Refactoring.Guru 카탈로그를 대조해 다시 쓴 것이다. Refactoring.Guru는 Interpreter를 다루지 않으며(22개), 클래스 범위 4개 분류는 GoF 원전 기준이므로 시험 직전 원전·기출로 재확인한다.

막히면 선생님(에이전트)에게 물어보자. "A와 B가 뭐가 달라?"가 가장 좋은 질문이다.
