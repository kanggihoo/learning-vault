Admin Client 설정: 운영 자동화를 위한 클라이언트

목표: Apache Kafka Documentation: AdminClient Configs를 근거로, AdminClient 설정 중 실제로 새로 알아야 할 것만 짚는다. 0020 레슨에서 손으로 했던 운영 작업(토픽 생성/삭제, 설정 변경, 클러스터 상태 조회)을 코드로 자동화할 때 쓰는 게 AdminClient다. 공통 클라이언트 설정(보안, 재시도, timeout)은 이미 0028 레슨에서 Producer 기준으로 배웠으니 여기서는 반복하지 않는다.

0. AdminClient는 왜 필요한가 — "손으로 하던 걸 코드로"

0020 레슨에서 배운 운영 작업들 — 토픽 만들기, 설정 바꾸기, 브로커/파티션 상태 조회하기 — 은 원래 CLI 도구(kafka-topics.sh 같은)로 사람이 직접 실행하던 것이다. 그런데 이걸 애플리케이션 코드나 운영 자동화 스크립트 안에서 실행하고 싶을 때가 있다 — 예를 들어 "신규 테넌트가 가입하면 자동으로 전용 토픽을 만들어준다"거나, "배포 파이프라인에서 토픽 설정이 원하는 값과 다르면 자동으로 맞춘다" 같은 경우다. AdminClient는 이런 관리 작업을 Producer/Consumer와 똑같은 방식(Kafka 프로토콜로 브로커와 통신)으로 코드에서 호출할 수 있게 해주는 클라이언트다.

그래서 AdminClient 설정 대부분(bootstrap.servers, security.protocol, ssl.*, sasl.*, retries, request.timeout.ms 등)은 Producer/Consumer와 똑같다 — "클러스터에 어떻게 연결하고, 인증하고, 실패하면 어떻게 재시도할지"는 어떤 클라이언트든 같은 문제이기 때문이다. 자세한 설명은 0028 — Producer 설정을 참고하고, 아래는 AdminClient에서만 특별히 알아둘 것 두세 가지만 다룬다.

1. bootstrap.controllers — KRaft 환경에서 컨트롤러에 바로 연결하기

보통 클라이언트는 bootstrap.servers로 브로커에 접속해서 클러스터 전체를 알아간다. 그런데 0022 레슨에서 배운 KRaft controller quorum 자체를 다뤄야 하는 관리 작업(예: quorum 상태 확인, controller 추가/제거)은 브로커가 아니라 controller에 직접 연결해야 한다. bootstrap.controllers가 이 용도의 설정이다 — 형식은 bootstrap.servers와 같은 host:port 목록이다.

설정연결 대상쓰는 경우
bootstrap.serversBroker토픽 관리, 설정 변경 등 일반적인 관리 작업
bootstrap.controllersKRaft ControllerController quorum 자체를 다루는 작업(0022의 Metadata Quorum Tool 등)

2. default.api.timeout.ms — "이 요청까지 다 합쳐서 언제까지"

Producer/Consumer의 request.timeout.ms가 네트워크로 보낸 요청 하나의 응답을 얼마나 기다릴지를 정한다면, AdminClient의 default.api.timeout.ms(기본 60초)는 API 호출 하나 전체의 최종 기한이다. 예를 들어 토픽 생성 하나가 내부적으로 재시도를 여러 번 거친다면, 그 재시도를 다 포함해서 60초 안에 끝나지 않으면 API 호출 자체가 실패로 끝난다. 호출할 때 timeout 파라미터를 따로 안 주면 이 값이 기본으로 적용된다.

3. 재시도와 "멱등적이지 않은" 관리 작업

토픽 생성처럼 "두 번 하면 다른 결과"인 작업을 재시도할 때

Producer의 멱등성 전송(0019 레슨 참고)은 "같은 메시지를 여러 번 보내도 결과가 한 번 보낸 것과 같다"는 보장이었다. 그런데 토픽 생성 같은 관리 작업은 다르다 — 첫 번째 요청이 실제로는 성공했는데 응답만 못 받아서 클라이언트가 재시도하면, 두 번째 요청은 "이미 존재하는 토픽"이라는 에러(TopicExistsException)를 받게 된다. 이건 진짜 실패가 아니라 재시도가 만든 착시일 수 있으므로, 자동화 스크립트를 짤 때는 이 에러를 "이미 원하는 상태에 도달한 것"으로 처리하는 로직을 넣어주는 게 안전하다 — AdminClient가 알아서 구분해주지 않는다.
