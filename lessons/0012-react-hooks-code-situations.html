React Hooks 실제 코드 상황별 예제

목표: Hook 설명을 암기하지 않고, 실제 컴포넌트 상황에서 어떤 Hook을 골라야 하는지 코드로 판단한다. 먼저 React Hooks: 언제 어떤 Hook을 쓰는가를 읽으면 기준이 더 선명하다.

1. useEffect: 검색어가 바뀌면 서버에서 다시 가져오기

상황: 사용자가 검색어를 입력하면 서버 API를 호출해서 결과 목록을 보여줘야 한다. 서버는 React 밖의 시스템이므로 렌더링 결과를 서버 요청과 동기화해야 한다.

잘못된 직감: “렌더링할 때 fetch를 바로 호출하면 되지 않을까?” 그러면 렌더링 중 side effect가 발생하고, 상태 변경 때문에 렌더링과 요청이 꼬일 수 있다. 

import { useEffect, useState } from "react";

function ProductSearch({ query }) {
  const [items, setItems] = useState([]);
  const [status, setStatus] = useState("idle");

  useEffect(() => {
    if (query.trim() === "") {
      setItems([]);
      setStatus("idle");
      return;
    }

    let ignore = false;

    async function loadProducts() {
      setStatus("loading");

      try {
        const response = await fetch(`/api/products?q=${encodeURIComponent(query)}`);
        const data = await response.json();

        if (!ignore) {
          setItems(data.items);
          setStatus("success");
        }
      } catch {
        if (!ignore) {
          setStatus("error");
        }
      }
    }

    loadProducts();

    return () => {
      ignore = true;
    };
  }, [query]);

  if (status === "loading") return <p>검색 중...</p>;
  if (status === "error") return <p>검색 실패</p>;

  return (
    <ul>
      {items.map((item) => (
        <li key={item.id}>{item.name}</li>
      ))}
    </ul>
  );
}

왜 useEffect인가: query라는 React 값이 바뀔 때마다 외부 시스템인 서버와 결과를 맞춰야 하기 때문이다. 이전 요청보다 늦게 도착한 응답이 최신 화면을 덮지 않도록 cleanup에서 ignore를 바꾼다.

2. useRef: interval id를 보관하지만 화면은 다시 그리지 않기

상황: 타이머를 시작/정지해야 한다. interval id는 기억해야 하지만 화면에 직접 보여줄 값은 아니다. 

import { useRef, useState } from "react";

function Stopwatch() {
  const [seconds, setSeconds] = useState(0);
  const intervalIdRef = useRef(null);

  function start() {
    if (intervalIdRef.current !== null) {
      return;
    }

    intervalIdRef.current = setInterval(() => {
      setSeconds((current) => current + 1);
    }, 1000);
  }

  function stop() {
    clearInterval(intervalIdRef.current);
    intervalIdRef.current = null;
  }

  return (
    <section>
      <p>{seconds}초</p>
      <button onClick={start}>시작</button>
      <button onClick={stop}>정지</button>
    </section>
  );
}

왜 useRef인가: seconds는 화면에 보이므로 state다. intervalId는 화면에 안 보이고 값 변경만 기억하면 되므로 ref다.

3. useMemo: 큰 목록 필터링 결과 재사용하기

상황: 상품 목록이 크고, 검색어/카테고리가 바뀔 때만 필터링을 다시 하고 싶다. 다른 state가 바뀌는 렌더링에서는 필터링 결과를 재사용한다. 

import { useMemo, useState } from "react";

function ProductList({ products }) {
  const [query, setQuery] = useState("");
  const [category, setCategory] = useState("all");
  const [selectedId, setSelectedId] = useState(null);

  const visibleProducts = useMemo(() => {
    return products
      .filter((product) => {
        return category === "all" || product.category === category;
      })
      .filter((product) => {
        return product.name.toLowerCase().includes(query.toLowerCase());
      });
  }, [products, query, category]);

  return (
    <section>
      <input value={query} onChange={(event) => setQuery(event.target.value)} />
      <select value={category} onChange={(event) => setCategory(event.target.value)}>
        <option value="all">전체</option>
        <option value="book">도서</option>
        <option value="tool">도구</option>
      </select>

      <ul>
        {visibleProducts.map((product) => (
          <li key={product.id}>
            <button onClick={() => setSelectedId(product.id)}>
              {product.name}
            </button>
          </li>
        ))}
      </ul>

      <p>선택한 상품: {selectedId ?? "없음"}</p>
    </section>
  );
}

왜 useMemo인가: selectedId만 바뀌어도 컴포넌트는 다시 렌더링된다. 하지만 필터링은 products, query, category가 같으면 다시 할 필요가 없다.

4. useCallback: memo된 자식에게 같은 함수 참조 넘기기

상황: 행 컴포넌트를 memo로 감쌌다. 부모가 다시 렌더링될 때마다 함수 prop이 새로 만들어지면 자식도 다시 렌더링될 수 있다. 

import { memo, useCallback, useState } from "react";

const TodoRow = memo(function TodoRow({ todo, onToggle }) {
  console.log("render row:", todo.id);

  return (
    <li>
      <label>
        <input
          type="checkbox"
          checked={todo.done}
          onChange={() => onToggle(todo.id)}
        />
        {todo.title}
      </label>
    </li>
  );
});

function TodoList({ initialTodos }) {
  const [todos, setTodos] = useState(initialTodos);
  const [keyword, setKeyword] = useState("");

  const handleToggle = useCallback((id) => {
    setTodos((currentTodos) => {
      return currentTodos.map((todo) => {
        return todo.id === id ? { ...todo, done: !todo.done } : todo;
      });
    });
  }, []);

  return (
    <section>
      <input
        value={keyword}
        onChange={(event) => setKeyword(event.target.value)}
        placeholder="검색어"
      />

      <ul>
        {todos.map((todo) => (
          <TodoRow key={todo.id} todo={todo} onToggle={handleToggle} />
        ))}
      </ul>
    </section>
  );
}

왜 useCallback인가: keyword가 바뀌어 부모가 다시 렌더링되어도 handleToggle 함수 참조는 그대로라서 memo된 자식의 불필요한 렌더링을 줄일 수 있다.

5. useReducer: 폼 저장 흐름을 action으로 정리하기

상황: 글 작성 폼에는 제목, 내용, 저장 중 여부, 에러가 있다. 입력 변경, 저장 시작, 저장 성공, 저장 실패가 모두 state를 바꾼다. 

import { useReducer } from "react";

const initialState = {
  title: "",
  body: "",
  isSaving: false,
  error: null
};

function editorReducer(state, action) {
  switch (action.type) {
    case "titleChanged":
      return { ...state, title: action.title };
    case "bodyChanged":
      return { ...state, body: action.body };
    case "saveStarted":
      return { ...state, isSaving: true, error: null };
    case "saveSucceeded":
      return { ...state, isSaving: false };
    case "saveFailed":
      return { ...state, isSaving: false, error: action.message };
    default:
      throw new Error("Unknown action: " + action.type);
  }
}

function PostEditor() {
  const [state, dispatch] = useReducer(editorReducer, initialState);

  async function savePost() {
    dispatch({ type: "saveStarted" });

    try {
      await fetch("/api/posts", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
          title: state.title,
          body: state.body
        })
      });

      dispatch({ type: "saveSucceeded" });
    } catch {
      dispatch({ type: "saveFailed", message: "저장하지 못했습니다." });
    }
  }

  return (
    <section>
      <input
        value={state.title}
        onChange={(event) => {
          dispatch({ type: "titleChanged", title: event.target.value });
        }}
      />

      <textarea
        value={state.body}
        onChange={(event) => {
          dispatch({ type: "bodyChanged", body: event.target.value });
        }}
      />

      <button onClick={savePost} disabled={state.isSaving}>
        {state.isSaving ? "저장 중..." : "저장"}
      </button>

      {state.error !== null && <p>{state.error}</p>}
    </section>
  );
}

왜 useReducer인가: 상태 필드가 여러 개이고, 상태 변경 이유도 여러 개다. reducer로 모으면 “어떤 사건이 어떤 상태 변화를 만드는지”가 한곳에 드러난다.

6. 상황별 선택 요약

상황 Hook 판단 기준
검색어 변경에 맞춰 서버 요청 useEffect 서버라는 외부 시스템과 동기화한다.
interval id 보관 useRef 값은 기억해야 하지만 화면에는 안 보인다.
큰 배열 필터링 결과 재사용 useMemo 계산 결과를 dependency 기준으로 캐시한다.
memo 자식에게 함수 prop 전달 useCallback 함수 참조를 안정화한다.
복잡한 폼 저장 상태 관리 useReducer 상태 변경 규칙을 action으로 모은다.
