React Hooks: 언제 어떤 Hook을 쓰는가

목표: useEffect, useRef, useMemo, useCallback, useReducer를 이름이 아니라 “해결하려는 문제”로 고를 수 있게 만든다.

1. 먼저 이 질문부터 한다

1. 화면에 보여야 하는 값인가?
   yes -> useState 또는 useReducer
   no  -> useRef 가능

2. React 밖의 시스템과 연결해야 하는가?
   yes -> useEffect
   no  -> useEffect부터 쓰지 않는다

3. 계산이 비싸거나 참조가 안정적이어야 하는가?
   계산 결과 -> useMemo
   함수 참조 -> useCallback

4. 상태 변경 규칙이 여러 갈래로 복잡한가?
   yes -> useReducer

가장 흔한 실수는 useEffect를 “렌더링 뒤에 뭔가 실행하는 곳”으로만 외우는 것이다. React 공식 문서 기준으로 Effect의 핵심 목적은 컴포넌트를 외부 시스템과 동기화하는 것이다. 외부 시스템이 없다면 Effect가 필요 없는 경우가 많다.

2. Hook별 한 문장

Hook 정확한 역할 쓸 때 헷갈리면 이렇게 기억
useEffect 렌더링 결과를 React 밖의 시스템과 맞춘다. API 요청, 이벤트 구독, 타이머, WebSocket, 외부 위젯 연결. “밖이랑 연결.”
useRef 렌더링과 무관한 값을 같은 객체에 보관한다. DOM 노드, timer id, 이전 값, mutable flag 보관. “기억하지만 다시 그리진 않음.”
useMemo 의존성이 안 바뀌면 계산 결과를 재사용한다. 비싼 계산, 큰 배열 filter/sort, memo된 자식에게 넘길 객체. “값 캐시.”
useCallback 의존성이 안 바뀌면 함수 참조를 재사용한다. memo된 자식에게 함수 prop 전달, Effect 의존성 안정화. “함수 캐시.”
useReducer 현재 state와 action으로 다음 state를 계산한다. 상태 필드가 많고 변경 규칙이 여러 이벤트에 흩어질 때. “상태 변경 규칙표.”

3. useEffect: 외부와 맞출 때만

useEffect는 렌더링이 끝난 뒤 실행된다. 하지만 “렌더링 후 실행”보다 중요한 말은 “외부 시스템과 동기화”다. 서버, 브라우저 이벤트, 타이머, 외부 라이브러리처럼 React가 직접 관리하지 않는 대상이 있을 때 쓴다. 

useEffect(() => {
  const id = setInterval(() => {
    console.log("tick");
  }, 1000);

  return () => {
    clearInterval(id);
  };
}, []);

기억법: setup이 있으면 cleanup도 생각한다. 연결했으면 끊고, 등록했으면 해제하고, 시작했으면 멈춘다.

4. useRef: 값은 보관하지만 렌더링은 안 한다

useRef는 { current: ... } 모양의 같은 객체를 다음 렌더링에도 돌려준다. ref.current를 바꿔도 React는 화면을 다시 그리지 않는다. 

function SearchBox() {
  const inputRef = useRef(null);

  function focusInput() {
    inputRef.current.focus();
  }

  return (
    <>
      <input ref={inputRef} />
      <button onClick={focusInput}>Focus</button>
    </>
  );
}

화면에 보여야 하는 값이면 useRef가 아니라 state다. useRef는 “React가 몰라도 되는 값”에 적합하다.

5. useMemo와 useCallback: 둘 다 성능 최적화다

useMemo는 함수 실행 결과를 캐시한다. useCallback은 함수 자체를 캐시한다. 코드가 이 Hook들 없이 동작하지 않는다면 설계 문제를 먼저 고쳐야 한다. 

const visibleItems = useMemo(() => {
  return items.filter((item) => item.category === category);
}, [items, category]);

const handleSelect = useCallback((id) => {
  setSelectedId(id);
}, []);

기억법: useMemo(() => 계산결과, deps), useCallback(함수, deps). useCallback(fn, deps)은 대략 useMemo(() => fn, deps)처럼 생각하면 된다.

6. useReducer: 상태 변경을 action으로 정리한다

useReducer는 복잡한 상태를 “이벤트 이름과 다음 상태 계산”으로 정리한다. setState가 여러 곳에서 서로 다른 방식으로 흩어질 때 특히 좋다. 

const initialState = {
  title: "",
  body: "",
  isSaving: false,
  error: null
};

function reducer(state, action) {
  switch (action.type) {
    case "titleChanged":
      return { ...state, title: action.title };
    case "saveStarted":
      return { ...state, isSaving: true, error: null };
    case "saveFailed":
      return { ...state, isSaving: false, error: action.error };
    default:
      throw new Error("Unknown action: " + action.type);
  }
}

function Editor() {
  const [state, dispatch] = useReducer(reducer, initialState);

  return (
    <input
      value={state.title}
      onChange={(event) => {
        dispatch({ type: "titleChanged", title: event.target.value });
      }}
    />
  );
}
