PR Rebase and merge가 왜 어떤 때는 괜찮고, 어떤 때는 꼬이나

핵심: PR의 Rebase and merge는 대상 브랜치의 기존 커밋을 바꾸지 않는다. 하지만 대상 브랜치가 누군가의 force push로 이미 갈아엎어진 상태라면, 다른 사람 PR의 기준점이 깨져서 중복 커밋처럼 보일 수 있다.

1. 정상적인 PR Rebase and merge

대상 브랜치 origin/A가 안정적이고, 철수 PR에는 철수 커밋 C1만 있다.

대상 브랜치:
M1 -- M2 -- A1 -- A2
                  ▲
                  └─ origin/A

철수 PR 브랜치:
M1 -- M2 -- A1 -- A2 -- C1
                        ▲
                        └─ chulsoo/C1

GitHub가 PR에서 볼 수 있는 차이는 명확하다.

철수 PR의 고유 커밋:
C1

Rebase and merge 결과:

M1 -- M2 -- A1 -- A2 -- C1'
                              ▲
                              └─ origin/A

문제 없음. 대상 브랜치의 기존 A1, A2는 그대로 있고, 철수 커밋 C1만 뒤에 붙었다.

2. 누군가 공유 브랜치 origin/A를 rebase 후 force push함

원래 origin/A는 이랬다.

옛 origin/A:
M1 -- M2 -- A1 -- A2
                  ▲
                  └─ origin/A

철수는 이 옛 A2 위에서 작업했다.

철수 PR 브랜치:
M1 -- M2 -- A1 -- A2 -- C1
                        ▲
                        └─ chulsoo/C1

그런데 누군가 origin/A를 origin/main 위로 rebase하고 force push했다.

새 origin/A:
M1 -- M2 -- M3 -- A1' -- A2'
                            ▲
                            └─ origin/A

철수 PR 브랜치:
M1 -- M2 -- A1 -- A2 -- C1
                        ▲
                        └─ chulsoo/C1

사람 눈에는 A1', A2'가 A1, A2를 다시 만든 것처럼 보인다. 하지만 Git에게는 해시가 다른 별개의 커밋이다.

3. 이 상태에서 철수 PR을 Rebase and merge하면?

GitHub가 철수 PR을 볼 때, 공통 조상은 대략 M2가 된다.

새 origin/A:
M1 -- M2 -- M3 -- A1' -- A2'

철수 PR:
M1 -- M2 -- A1 -- A2 -- C1

공통 조상:
M2

그래서 GitHub가 철수 PR의 고유 커밋을 이렇게 볼 수 있다.

철수 PR의 고유 커밋처럼 보이는 것:
A1 -- A2 -- C1

그 상태에서 Rebase and merge를 하면 이런 결과가 될 수 있다.

M1 -- M2 -- M3 -- A1' -- A2' -- A1'' -- A2'' -- C1'
                                                  ▲
                                                  └─ origin/A

철수가 원한 건 C1만 반영되는 것이었다. 하지만 옛 A1, A2까지 철수 PR 변경처럼 다시 붙을 수 있다.

4. 철수가 원했던 진짜 결과

철수가 원한 건 이것이다.

M1 -- M2 -- M3 -- A1' -- A2' -- C1'
                                      ▲
                                      └─ origin/A

이걸 만들려면 철수는 자기 브랜치를 수동으로 정리해야 할 수 있다.

git fetch origin
git switch chulsoo/C1
git rebase --onto origin/A A2 chulsoo/C1

뜻:

A2 이후의 커밋만 origin/A 뒤로 옮겨라.
즉 C1만 살리고, 옛 A1/A2는 버려라.

5. 그래서 차이는 이것

정상 PR Rebase and merge
대상 브랜치가 안정적임.
PR 브랜치의 고유 커밋이 명확함.
예: C1만 붙이면 됨.

공유 브랜치 rebase force push 후 PR
대상 브랜치의 기준점이 바뀜.
다른 사람 PR의 공통 조상이 뒤로 밀림.
예: A1, A2, C1이 전부 PR 변경처럼 보일 수 있음.

결론

PR Rebase and merge 자체가 나쁜 게 아니다. 문제는 PR의 대상 브랜치가 force push로 갈아엎어져서, 다른 사람 PR이 어디서부터 자기 변경인지 잃어버리는 상황이다.
