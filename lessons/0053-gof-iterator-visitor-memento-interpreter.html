Iterator · Visitor · Memento · Interpreter

행위 패턴의 나머지 넷이다. 앞 묶음처럼 서로 닮아서 헷갈리는 쌍이 아니라, 각각 따로 떨어진 질문에 답한다: 순회(Iterator), 연산 분리(Visitor), 상태 저장·복원(Memento), 문법 해석(Interpreter). 그래서 이번엔 "이 키워드가 나오면 이것"으로 빨리 알아보는 연습이 중심이다.

§0 · 워밍업 — 지난 묶음 4문제

신호 요약. 구조: 자기와 같은 타입의 리스트를 들고 재귀하면 Composite / 여러 서브시스템 앞의 새 창구는 Facade / 기능·구현 두 계층 분리는 Bridge / 공유로 아끼면 Flyweight.

R1. class Folder implements Node { List<Node> children; int size(){ sum of children.size() } }

R2. 나무 1만 그루가 모델·텍스처 객체 하나를 공유하고 위치만 따로 가진다.

R3. 구독자 목록을 들고 있다가 값이 바뀌면 전원의 onChange()를 호출한다.

R4. 래퍼가 원본과 같은 인터페이스이고, 권한이 없으면 원본을 호출하지 않고 예외를 던진다.

패턴답하는 질문비유키워드

§2 · Iterator (반복자) — 속을 숨기고 순서대로 꺼낸다

이론. 리스트든 트리든 해시든, 내부 표현을 드러내지 않고 요소를 하나씩 순서대로 꺼내는 공통 방법(hasNext(), next())을 제공한다. 별칭 Cursor.

비유. TV 리모컨의 채널 다음/이전 버튼. 방송국이 채널을 어떻게 보관하든 누르면 다음 채널이 나온다.

interface Iterator<T> { boolean hasNext(); T next(); }
Iterator<String> it = list.iterator();      // 리스트 내부 구조를 몰라도 된다
while (it.hasNext()) System.out.println(it.next());

Java의 java.util.Iterator가 그대로 이 패턴이다 (Javadoc: "An iterator over a collection", hasNext()/next()). for-each 문도 내부에서 이터레이터를 쓴다. 출처: Refactoring.Guru — Iterator.

§3 · Visitor (방문자) — 연산을 밖으로 뺀다

이론. 데이터 구조(요소 클래스들)는 그대로 두고, 그 위에 할 새 연산을 별도 클래스(Visitor)로 만든다. 요소는 accept(visitor)만 가지고 있고, 그 안에서 visitor.visit(this)를 호출한다. 이렇게 두 번 호출해 요소 타입에 맞는 메서드가 자동 선택되는 것이 더블 디스패치다. 새 연산이 필요하면 Visitor 클래스만 추가한다.

비유. 집(데이터)은 그대로인데 검침원, 배달원, 수리공(연산)이 번갈아 방문해 각자 일을 한다. 집은 "들어오세요"(accept)만 안다.

interface Shape { void accept(ShapeVisitor v); }
class Circle implements Shape { public void accept(ShapeVisitor v) { v.visit(this); } }
class Square implements Shape { public void accept(ShapeVisitor v) { v.visit(this); } }

interface ShapeVisitor { void visit(Circle c); void visit(Square s); }
class AreaVisitor implements ShapeVisitor {          // 새 연산 = 새 클래스
    public void visit(Circle c) { /* 원 넓이 */ }
    public void visit(Square s) { /* 사각형 넓이 */ }
}
shape.accept(new AreaVisitor());                     // 요소가 알아서 맞는 visit을 호출

JDK 예: FileVisitor를 Files.walkFileTree에 넘기면 파일 트리의 각 항목에서 visitFile, preVisitDirectory 같은 메서드가 호출된다. 출처: Refactoring.Guru — Visitor.

알아볼 표지. 요소 클래스마다 accept(Visitor v) { v.visit(this); }가 똑같이 들어 있고, Visitor 인터페이스에 요소 타입별 visit() 오버로드가 있다. 이 모양이면 거의 Visitor다.

§4 · Memento (메멘토) — 캡슐화를 지키며 저장·복원

이론. 객체의 내부 상태를 밖에 노출하지 않고 스냅샷(Memento)으로 꺼내 보관했다가, 필요할 때 그 상태로 복원한다. 핵심은 "private 필드를 공개하지 않고도 저장·복원"이다. 보관하는 쪽(Caretaker)은 내용을 못 열어 본다. 별칭 Token.

비유. 게임 세이브 파일. 게임이 자기 상태를 파일로 만들어 주고, 불러오면 그때로 돌아간다. 세이브 파일 관리자(메뉴)는 파일 안을 모른다.

class Editor {
    private String text;
    Snapshot save() { return new Snapshot(text); }          // 상태를 포장
    void restore(Snapshot s) { this.text = s.text; }        // 상태 복원
    static class Snapshot {                                  // 밖에서는 내용을 못 연다
        private final String text;
        private Snapshot(String t) { this.text = t; }
    }
}
Deque<Editor.Snapshot> undoStack = new ArrayDeque<>();     // Caretaker가 보관만 한다

Command와 함께 undo를 구현할 때 짝으로 쓴다 — Command가 동작하기 직전에 Memento로 상태를 저장한다 (Refactoring.Guru — Memento).

§5 · Interpreter (인터프리터) — 문법을 클래스로

이론. 간단한 언어의 문법 규칙 하나하나를 클래스로 만들고, 문장은 그 객체들의 트리로 표현해 interpret()를 재귀로 호출해 해석한다. 숫자 같은 끝(terminal)과, 더하기처럼 다른 규칙을 품는 가지(nonterminal)로 나뉜다 — Composite와 닮았다. GoF의 클래스 패턴 4개 중 하나다.

비유. 수식 계산기. "(1 + 2) * 3"을 숫자 객체와 연산자 객체의 트리로 만들고 루트에서 계산을 시작한다.

interface Expr { int interpret(); }
class Num implements Expr { int n; public int interpret() { return n; } }            // 끝
class Add implements Expr {                                                          // 가지
    Expr l, r;
    public int interpret() { return l.interpret() + r.interpret(); }
}
// (1 + 2) → new Add(new Num(1), new Num(2)).interpret()  == 3

한계: 이 패턴은 문자열을 파싱하지는 않는다(트리가 이미 만들어졌다고 가정). 문법이 복잡하면 파서가 더 적합하다 (SourceMaking — Interpreter). Refactoring.Guru 카탈로그에는 이 패턴이 없다.

§6 · 헷갈리는 쌍

쌍구분 질문
Visitor vs IteratorIterator는 꺼내는 순서를 정하고, Visitor는 꺼낸 요소에 무슨 일을 할지를 정한다. 둘을 함께 쓰기도 한다
Memento vs CommandMemento는 상태를 저장하고, Command는 동작을 저장한다. undo에서는 같이 쓴다
Interpreter vs Composite구조는 닮았다(트리·재귀). Interpreter는 그 트리가 문법을 표현해 해석한다는 점이 다르다

§8 · 한 문장으로 회수

하나씩 꺼내면 Iterator, accept/visit으로 연산을 빼면 Visitor, 상태를 저장·복원하면 Memento, 문법 트리를 해석하면 Interpreter.
