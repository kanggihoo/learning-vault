# MCP 2026-07-28 학습 시작 — 전제 속 두 층의 혼합을 첫 보정 지점으로

2026-09-14. 사용자가 MCP 2026-07-28 스펙 변경(블로그·changelog 링크 제공)과
"세션에 한 번에 다 불러오지 않고 점진적으로 불러오는 방식으로 바뀌었다"는 것을 배우고 싶다고 했다.
"MCP가 대충 무엇인지는 안다", "어려운 용어는 먼저 설명해 달라"고 명시했다.

**검증 결과 — 전제의 큰 그림은 맞고 층이 하나 섞여 있다** ([[0032-architecture-arc-completed]]의 NOTES 패턴 재현):
- 스펙이 바뀐 것은 **프로토콜 세션 제거(stateless)** 다. `initialize`·`Mcp-Session-Id`가 사라지고 매 요청이 `_meta`에 버전·capability를 싣는다. 이건 서버 확장성 문제다.
- "점진적으로 도구를 불러오는 것"은 **스펙(와이어)이 아니라 호스트가 LLM 컨텍스트에 무엇을 넣는가**의 문제다. 서버는 여전히 `tools/list`로 전부 준다. 공식 문서도 이걸 *Client Best Practices → Progressive Tool Discovery*(docs 2026-07-28)에 두었고, Anthropic API의 `defer_loading`/`tool_reference`, Claude Code의 `ENABLE_TOOL_SEARCH`가 구현체다.
- 두 "세션"이 다르다: (a) MCP 프로토콜 세션(제거됨) (b) LLM 대화 컨텍스트(점진 로딩이 일어나는 곳). 사용자 문장의 "세션"은 (b)였다.
- 스펙이 (b)를 **돕는** 지점은 있다: `ttlMs`/`cacheScope`(호스트 캐시), 결정적 `tools/list` 순서(프롬프트 캐시 히트), `subscriptions/listen`(캐시 무효화). 이걸 "스펙이 점진 로딩을 도입했다"로 읽으면 과장이다.

**Implications**
- 용어집을 먼저 만들었다(레퍼런스 0023 §1) — 사용자 요청이자, 두 층을 나누는 어휘(와이어/호스트/컨텍스트, 세션 두 뜻)가 있어야 보정이 가능해서다.
- 레슨을 둘로 나눴다: 0047 무상태 전환(프로토콜 층), 0048 점진 도구 로딩(호스트·컨텍스트 층). 한 레슨에 넣으면 층 구분 자체가 흐려진다.
- 사용자는 백엔드 개발자라 로드밸런서·sticky session·멱등 재시도·Cache-Control 어휘가 있다. 무상태 전환은 그 어휘로 바로 설명했다(`ttlMs` ≈ `max-age`, `requestState` ≈ 서명된 쿠키/JWT).
- 이해 확인은 아직 0. 퀴즈 반응과 되묻는 질문을 기다린다.
