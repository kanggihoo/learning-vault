# 두 종류의 이해, 그리고 내 계획에 있던 지도 구멍 — 2026-09-03

0036을 내놓은 뒤 사용자가 두 번 되물었다.

1. *"이것만 읽으면 되는거야??"*
2. *"내말은 되게 내용이 많지 않았나? 35, 36 내용만 이해하면 되는거냐고"*

**두 번째가 진짜 신호였다.** 첫 번째를 나는 "레슨 하나로 충분한가"로 읽고 층위 설명(레슨/치트시트/문서/외부출처)을
답했는데, 사용자가 실제로 물은 것은 **"문서는 이만큼 방대한데 네가 준 건 스케줄링 공식 하나다"** 였다.
그리고 그 지적이 맞았다.

## 진단 — 내가 놓친 것

나는 11레슨 아크를 **전이 가능한 개념(Type A)** 만으로 설계했다. 표적 자체는 옳다 —
"AI가 코드를 쓰니 리뷰 능력이 필요하다"는 미션에 맞다. 하지만 **프로젝트 전체를 조망하는 산출물이
아크에 하나도 없었다.**

그래서 사용자 입장에서 0036은 **공중에 떠 있었다.** 16장·60엔드포인트·18 WS 메시지·25테이블 중
어디에 속한 이야기인지 알 수 없는 상태에서 스케줄링 공식만 받았기 때문이다.

**`NOTES.md`에 내가 이미 적어 둔 규칙을 이번에 안 지켰다:**

> 구조를 배우는 요청에는 SVG 다이어그램을 직접 그려 넣는다. **텍스트 설명만으로는 "전체 지도"가 안 잡힌다.**

## 정리한 프레임 — 두 종류의 이해

| | Type A · 원리 | Type B · 이 프로젝트의 사실 |
|---|---|---|
| 예 | 시간은 누적하지 말고 절대 기준에서 다시 구한다 | 수수료 0.15%, 시드 1억, 부재 기준 50틱 |
| 전이 | **된다** | 안 된다 |
| 양 | 적다 (개념 12개) | **방대하다** (수백 개) |
| 배우는 법 | **레슨** — 한 번 익히면 영구 | **찾아본다** — 외우는 게 아니다 |
| AI가 틀리나 | **자주** | 거의 안 틀린다 (문서 보고 씀) |

**핵심: 두 표적에 서로 다른 산출물이 필요하다.** 레슨만으로는 Type B가 안 덮이고,
Type B를 레슨으로 만들면 암기 과제가 되어 실패한다. Type B의 올바른 형태는 **레퍼런스(지도)** 다.

**앞으로 규칙:** 방대한 실제 프로젝트를 다룰 때는 **개념 레슨 전에 지도 레퍼런스를 먼저 만든다.**
지도가 없으면 첫 레슨이 어디에 속하는지 알 수 없다.

## 만든 것 — `reference/0019` 프로젝트 지도

13개 절. 통독용이 아니라 찾아보는 문서다. 하루 타임라인 SVG(phase + 무료타임 + 암전 + IPO 4건),
영역 간 의존 그래프 SVG, 엔드포인트 약 60개 전체 표(권한·phase 포함), WS 18종 ↔ destination 4개,
테이블 25개, 게임 규칙 숫자 총정리, 미결 13건 + 결정 시한, 착수 전 선행 3건, 용어 사전.

§13에 **지도와 레슨의 역할 분담**을 명시하고, 11레슨 각각이 지도의 어느 절을 설명하는지 대응표를 넣었다.
이제 0037부터는 "지도 §6을 설명하는 레슨"으로 위치가 잡힌다.

## 0036의 개념으로 실제 모순을 하나 잡았다

지도 §2를 만들면서 **720초 그리드 검산을 IPO 편성표에 직접 적용**했다.

- **기능명세서 IPO 편성표**: 8건 전부가 `일차 재생 시작 11:05 + (경과 개월 × 12분)`과 정확히 일치.
- **`종목.md`의 "실제 등장 시각"**: 8건 전부 어긋난다. 카카오게임즈 12:25는 11:05로부터 80분 = **6.67개월**로
  12분의 배수가 아니다. 일관되게 약 16~24분 이르다.
- 게다가 `종목.md` 값으로는 공시가 상장 **3개월** 전이 되어 기획서 8장의 "2개월 전" 규칙도 깨진다.

**즉 기능명세서가 정본이고 `종목.md`가 낡은 값이다.** 지도 §2에 경고로 넣었다.

**이게 이 미션의 증명이다.** 0036에서 배운 "12분 배수인지 검산한다"가 문서 두 개의 불일치를 30초에 찾아냈다.
개념이 실제로 도구가 된 첫 사례이고, 사용자에게도 이 연결을 명시했다.
