# Web Vitals 학습 시작 — 완전 초심자, 목표는 리포트 읽기와 백엔드 책임 칸

2026-09-13. 사용자가 LCP · INP · CLS(Core)와 TTFB · FCP · TBT · DCL(보조)을 배우고 싶다고 요청했다.
AskUserQuestion으로 확정한 미션: **① 내 프로젝트 성능 개선(리포트 읽기) ② 백엔드 결정이 프론트 지표에 미치는 영향
③ 프론트 결과물 리뷰·판단 능력.** 수준은 "이름도 이번에 처음 들었다". 예시는 일반 웹 페이지.

**Implications**
- 완전 초심자라 **지도(레퍼런스 0022)를 레슨보다 먼저** 만들었다 — [[0030-two-types-of-understanding-and-the-map-gap]]·[[0031-architecture-vocabulary-baseline]]과 같은 순서.
  첫 레슨 0046은 지도의 타임라인 자체를 가르친다.
- 이 사용자는 백엔드 어휘(p99, 타임아웃, 캐싱)가 이미 있다 — [[0032-architecture-arc-completed]]. 75퍼센타일·TTFB는 그 어휘에 바로 걸어 설명하면 된다.
  LCP 예산에서 TTFB가 ~40%(≈1.0s)라는 표가 "백엔드의 칸"을 가장 명확히 보여준다.
- DCL은 Web Vitals가 아니고 **파서 이벤트**다. 사용자가 이걸 "보조 성능 지표"로 묶어 온 것 자체가 첫 보정 지점이다 —
  0046 §4에서 "화면 지표 6개 + 문서 상태 이벤트 1개"로 나눴다.
- 아크 예상: 0046 지도 → 0047 로딩 축(TTFB→FCP→LCP 4구간) → 0048 반응 축(INP 3구간·TBT·long task) → 0049 CLS 산식 → 0050 실제 리포트 읽고 리뷰 문장 만들기.
- 이해 확인은 아직 0이다. 퀴즈 결과나 되묻는 질문이 오면 이 기록을 갱신한다.
